Méthode du projet généalogie DUBART

1. Les couches

CoucheOùRôleQui écrit
1. Arbre initialsources/ (brut), base/*_arbre.csv (importé)Ce qui a été transmis, erreurs comprisesoutils/importer_arbre.py uniquement
2. Enquêtebase/ (autres CSV)Assertions, preuves, recherches, correctionsarchiviste-généalogiste, session principale
3. Validationoutils/valider.py, tests/, controles/Règles automatiques et contrôle indépendantvalidateur, agent contrôleur
4. Contextecontexte/ + assertions historiquesL'époque, avec des liens explicites aux personneshistorien
5. Romandossier/saga/, roman/dependances.csvŒuvre littéraireromancier

La base (base/) est la seule source de vérité. Les documents de dossier/ (preuves.md, jeanne-augustine.md, zones-d-ombre.md, contexte-historique.md) et la page publiée sont des vues ou des archives : en cas de désaccord, la base fait foi. zones-d-ombre.md et contexte-historique.md sont en quarantaine (synthèses d'agents non contrôlées, enregistrées comme sources synthese_agent).

2. Le modèle de données

Tous les fichiers sont des CSV UTF-8 (lisibles dans Excel ou Numbers). Le modèle est défini dans outils/modele.py ; base/schema.sql en est la traduction PostgreSQL (Supabase compris).

TableUne ligne =Points clés
personnes (+ personnes_arbre)une personneid stable (P… arbre, PN… ajoutées) ; nom de naissance
nomsun nom porténaissance, adoption, mariage, variante graphique, surnom ; lié à l'assertion qui l'atteste
identificationsune identité possiblecandidate / etablie / rejetee + raison ; empêche les fusions hâtives
sourcesun documenttype, cote, vues, lien, image locale, primaire oui/non, depend_de (copies), consultation réelle (consultée / non consultée / inaccessible), date et auteur
assertions (+ assertions_arbre)un fait atomiqueénoncé, statut, nature, confiance + justification, raisonnement, limite, autres hypothèses, remplace, auteur, date
assertion_personnesun lien assertion ↔ personnerôle : sujet, parent, conjoint, apparente, témoin, déclarant, mentionné, autre ; relatif_a = personne à laquelle le rôle se rapporte (parent de qui, conjoint de qui : obligatoire si l'assertion a plusieurs sujets) ; lien = parenté précise du rôle apparente (oncle, petit-gendre…), du point de vue de la personne liée. Les fiches ne déduisent la famille que de ces rôles (règle R14).
preuvesun lien assertion ↔ sourcesoutient / contredit / mentionne ; extrait exact ; lecture incertaine
recherchesune recherche menéequestion, sources consultées, résultat (y compris infructueuse ou inaccessible), conclusion, pistes
journalune correctionavant, après, raison ; on ne supprime jamais
documents_familleun des 82 documents de l'arbrerécupéré ou non ; lien vers la source une fois consulté
roman/dependancesun passage du romanassertion utilisée et usage (documenté, reconstitution, hypothèse narrative, invention)

Dates : texte ISO, éventuellement partiel (1873, 1873-09) ou qualifié (~1776 environ, <1847-03 avant, >1836 après). Une date inconnue reste vide.

3. Statuts, nature, confiance

Voir docs/GARDE-FOUS.md. Correspondance avec l'ancien vocabulaire : LU → verifie + fait_atteste/transcription ; VÉRIFIÉ (source publiée) → selon que la page a vraiment été ouverte, verifie + rapport_tiers ou non_verifie ; DÉDUIT → inference_historique ; HYPOTHÈSE → hypothese ; INFIRMÉ → contredit ou refute.

5. Les outils

python3 -I outils/importer_arbre.py        # réimporte l'arbre (couche 1) après un nouvel export Heredis
python3 -I outils/valider.py --details      # contrôle les garde-fous
python3 -I outils/fiche.py P5229            # fiche documentaire d'une personne
python3 -I outils/fiche.py --toutes         # toutes les fiches dans fiches/
python3 -I outils/impacts.py A0080          # ce qui dépend d'une assertion ou d'une personne
python3 -I -m unittest discover -s tests -v # tests des garde-fous
python3 -I outils/generer_schema_sql.py     # régénère base/schema.sql

6. Corriger une erreur

  1. Ne pas effacer la ligne fautive. Changer son statut (contredit, refute, non_resolu…) ou créer une nouvelle assertion avec remplace = l'ancienne.
  2. Ajouter la preuve contraire dans preuves.csv (rôle contredit).
  3. Ajouter une entrée dans journal.csv (avant, après, raison).
  4. Lancer outils/impacts.py <id> pour voir les fiches, identifications et passages du roman à réexaminer.
  5. Lancer outils/valider.py. Une assertion de l'arbre ne se corrige jamais dans *_arbre.csv : on ajoute une preuve contraire et une entrée de journal (sa fiche l'affichera « contredit »).

7. Avant d'écrire du roman

  1. outils/valider.py --details : aucun avertissement R13 non traité sur les passages concernés.
  2. Le contrôleur est passé sur les faits que le chapitre utilise.
  3. Les choix narratifs sur les points non résolus (ex. qui est la mère de Jeanne) sont déclarés comme hypothèses narratives dans roman/dependances.csv.

8. Passage futur à PostgreSQL / Supabase

  1. Créer les tables : psql < base/schema.sql (ou l'éditeur SQL de Supabase).
  2. Importer dans l'ordre : personnes (personnes_arbre.csv puis personnes.csv), sources, assertions (assertions_arbre.csv puis assertions.csv), noms, identifications, assertion_personnes (les deux fichiers), preuves (les deux), recherches, recherche_assertions, journal, documents_famille, dependances. Commande : \copy table from 'fichier.csv' csv header.
  3. Les règles de outils/valider.py restent à exécuter (elles ne sont pas toutes exprimables en contraintes SQL) : il faudra alors le faire lire la base Postgres au lieu des CSV (seul outils/base.py est à adapter).

9. Limites connues

  • Les tests vérifient la forme (une source, un statut, un journal), pas que la source dit réellement ce qu'on lui fait dire : c'est le rôle du contrôleur et, en dernier ressort, d'un humain.
  • consultation = consultee repose sur la déclaration de celui qui saisit ; rien ne prouve techniquement qu'une page a été ouverte. Les outils web utilisés jusqu'ici renvoient des résumés de pages : une page lue ainsi est notée consultée avec cette réserve dans note.
  • La détection des homonymes est naïve (nom + prénoms identiques).
  • Les 82 documents de la famille ne sont pas encore récupérés.
  • Les faits historiques généraux utilisés par le roman ne sont pas encore vérifiés (7 avertissements R13 au 28/10/2026).
  • La page publiée « Concession 542 » n'est plus synchronisée avec la base ; elle sera régénérée depuis la base plus tard.

La Maison Dubart

Ce site est le dossier documentaire du roman La Maison Dubart. Il prolonge la généalogie de Jacques et Sylvette Robert, reprise par Jessica Robert avec Claude Code et des agents (archiviste, historien, contrôleur, romancier). La base fait foi : rien n'y est présenté comme un fait sans son statut.
